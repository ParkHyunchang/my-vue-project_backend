# TEAM-31 읽기 전용 준비도 판정

재현: 백엔드 저장소에서 `python tools/team31_readiness.py`, `python -m unittest discover -s tools -p team31_test.py -v`.

판정: 비교 대상 baseline/pause6/vol_entry 세 개 모두 실계좌 승인 불가. 각 전략은 엄격한 과거 6개 검증 셀 중 2개만 통과했다. 기존 승인 기준을 변경하지 않았으며, 신규 후보·관찰 계정·예약 실행을 등록하지 않았다.

| 대상 | 실행 엔진 지원 | 과거 검증 | 새로운 거래일/체결 | 판정 |
|---|---|---|---|---|
| baseline | team24-daily-v1 지원, 소스 pin 일치 | 2/6 | 기존 연구실 0일/0회 | 기존 가상 관찰 기준선 |
| pause6 | 미지원 | 2/6 | 미등록 | 하락폭 비교용 연구 후보 |
| vol_entry | 미지원 | 2/6 | 미등록 | 작은 개선 폭의 연구 비교군 |

public-smoke의 기존 연구실 등록 시각은 2026-11-21 16:39:40 UTC, 자료 마지막 날짜는 11월 20일이다. 활성 가상 계정은 `balanced_trend:recovery_vol`이며, 여섯 shadow 모두 새로운 거래일·체결이 없다. SQLite를 `mode=ro`와 `query_only`로 열었고 읽기 전후 DB SHA256이 같음을 확인했다. 키 파일과 운영 DB를 읽지 않았다.

`scheduler.json`이 없어 프로그램 기동 시 예약 실행 기본값은 false다. 이것은 프로세스가 현재 실행 중인지 확인했다는 뜻이 아니다. 이번 도구는 서버·스케줄러를 켜지 않는다.

TEAM-30의 48개 원본 결과 해시가 독립 감사 기록과 일치하고, 요약이 원본과 정확히 일치하며, 여덟 전략 각각 6개 셀의 판정이 일치함을 다시 확인했다. 새 시장자료를 수집하거나 새 수익률 실험을 실행한 결과는 아니다. 연구 코드 5개 파일의 현재 합성 해시, Python 배포 pin, Java 배포 pin, 기존 연구실 DB의 소스 해시가 일치한다. 정확한 해시와 전략 버전은 `readiness.json`에 있다.

사용자 제공 현금 35.48달러·JEPQ 3주는 인지했지만 현재 가격·평가액·위험관리 최고자산값·실제 체결은 이 도구의 검증 대상이 아니다. 10%는 차단 조건이며 갭·체결 지연으로 실제 손실이 이를 초과할 수 있다. 과거 수익 조건 실패는 forward 관찰 60일을 기다리는 것만으로 해결되지 않는다.

테스트: 6개 통과. 누락·중복 셀 거부, 비유한 수치 거부, 강제정지/미청산 거부, forward 기록으로 과거 실패를 덮지 않음, 실제 저장 결과 무결성, DB 신규 생성 금지·읽기 전후 불변을 확인했다. 최초 테스트의 Windows SQLite 핸들 해제 오류는 연결을 명시적으로 닫도록 수정한 뒤 재검증했다.
